# Architecture decision records

Create an ADR when a decision:

- replaces or tightly couples a core runtime component;
- changes a security or trust boundary;
- introduces a durable data/configuration format;
- establishes a public CLI/API compatibility promise;
- selects deployment, packaging, or persistence strategy; or
- is expensive to reverse.

Routine dependencies, tests, refactors, and local implementation choices do not need ADRs. Copy the existing
numbered format, record context/decision/consequences, and keep superseded ADRs with links to their replacement.
